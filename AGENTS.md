# Правила для ИИ-разработчика (Codex / GPT)

Проект: личное iOS-приложение Finance Test (Swift, SwiftUI, iOS 26+) для учёта операций Яндекс Банка. Владелец — Дмитрий, общение по-русски, коротко и по делу. Ведущий разработчик и проверяющий — Claude: он пишет ТЗ этапов, проверяет накопленные изменения и сливает их в `main`.

## Рабочий цикл
1. Работай только в ветке текущего этапа `stage-NN` (узнать: `git branch --show-current`). В `main` не коммить и не пушь никогда.
2. После правок запусти локальные проверки и не отправляй ничего при красном результате:
   `powershell -NoProfile -ExecutionPolicy Bypass -File .local\check.ps1`
3. В каждой сборке подними версию: в `YandexFinance.xcodeproj/project.pbxproj` четыре строки `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` (например 40.1 → 40.2) и первую строку README `Текущий номер сборки — …` плюс короткий раздел «Изменения …» сверху README. Проверка `reliability.test.js` сверяет эти номера.
4. Новый `.swift` файл добавь в `project.pbxproj` (PBXFileReference, PBXBuildFile, группа YandexFinance, Sources) — по образцу `AccountsView.swift`.
5. Коммит с понятным сообщением на английском, затем:
   `git push` (если просит вход — пусть пользователь войдёт в окне браузера).
6. Сборка и IPA:
   - `powershell -NoProfile -ExecutionPolicy Bypass -File .local\ci.ps1 -Action run -Branch stage-NN` — запускает GitHub Actions и ждёт результат (5–15 минут, очередь macOS бывает долгой; «job was not acquired by Runner» — сбой GitHub, просто запустить ещё раз);
   - при ошибке там же будут последние строки лога — исправь и повтори;
   - **IPA в iCloud Drive → «Finance Test» всегда кладёт Claude (последняя сборка ведущего). Твои сборки (GPT) туда не кладём: скачивай с ключом `-NoICloud` (`ci.ps1 -Action ipa -RunId <id> -NoICloud`), файл остаётся в `%TEMP%\finance-ipa`; пользователю напиши версию и путь. Так владелец всегда видит в iCloud сборку Claude и не путает версии.**
   - (для Claude) при успехе: `... ci.ps1 -Action ipa -RunId <id>` скачивает `FinanceTest-<версия>.ipa` и сам кладёт его в **iCloud Drive → «Finance Test»** (iCloud для Windows синхронизирует папку в «Файлы» на iPhone; там всегда только последняя сборка). Ссылки на файлы Windows не давай — напиши: «IPA <версия> в iCloud Drive → Finance Test». Если скрипт пишет, что iCloud Drive не запущен, скажи об этом пользователю.
7. Не утверждай, что что-то собралось или тесты прошли, если ты этого не запускал. Показывай реальный вывод команд.
8. Как только сборка зелёная и IPA в iCloud — **сразу** сообщи пользователю одной строкой: «IPA <версия> в iCloud Drive → Finance Test, проверить: …». Не копи несколько версий молча.

## Сборки GitHub — не отлаживать методом тыка
Один прогон macOS-сборки — 2–15 минут. Восемь красных сборок подряд = час впустую. Правила:
- **Не больше 2 красных сборок подряд на одну проблему.** После второй — остановись, напиши пользователю что не получается (текст ошибки из лога), и предложи передать Claude. Не продолжай гадать.
- **Не делай коммиты только ради диагностики** (печать координат, «посмотреть что выйдет»). Диагностику печатай в самом тесте при падении (`fputs` в тесте), одной сборкой.
- Перед пушем найди в логе прошлой сборки все ошибки сразу: `ci.ps1 -Action log -RunId <id> -Grep "error:|FAIL"` — исправляй все, а не первую.
- Код с SwiftUI/UIKit/PDFKit на Windows не компилируется. Поэтому пиши его маленькими шагами, по образцу уже работающего кода в проекте, без новых API, которых нет в соседних файлах. Новые API iOS 26 (glassEffect и т.п.) — только если такое же использование уже собирается в проекте.
- Чистую логику (разбор, сопоставление, расчёты) выноси в функции без UIKit/PDFKit — их проверяет `check.ps1` на Windows за секунды. В CI должно попадать только то, что нельзя проверить локально.
- Жесты, анимации и внешний вид на ПК проверить нельзя. Меняй их минимально, по одной проблеме за сборку, и в сообщении пользователю перечисли, что именно проверить пальцем.

## Что нельзя без ТЗ от Claude
- `Vault.swift` (хранилище и ключ шифрования), `StatementImporter.swift`, `Collector.js`, классификатор и расчёты в `FinanceEngine.swift` (доходы, расходы, возвраты, прогноз, запас), расчёты отчётов в `ReportEngine.swift` и остатков в `Models.swift` (`accountBalancesReconstructed`), `.github/`, `scripts/`.
- Любая финансовая логика — только вместе с тестами в `Tests/FinanceEngineTests.swift`.
- Не удалять и не перезаписывать данные пользователя; новые поля в `SavedHistory` — только необязательные (старые данные должны открываться).
- Никаких реальных банковских данных, выписок, токенов в репозитории (он публичный).
- В тестах и документах — только выдуманные имена, телефоны (маскированные `000-00-00`) и получатели. Это проверяет `Tests/privacy.test.js`: он запускается в `check.ps1`, перед каждым коммитом (git-хук) и в GitHub. Если он нашёл данные — замени их выдуманными; придуманное «Имя Отчество Ф.» добавь в `SYNTHETIC_NAMES` в этом файле. Список слов из реальных выписок лежит только в `.local/private-words.txt` — не копируй его содержимое никуда.

## Где что
- `YandexFinance/OperationsHomeView.swift` — главный экран (периоды, доходы/расходы, остаток, запас, история);
- `ForecastDetailView.swift` — прогноз на месяц; `AccountsView.swift` — счета и группы; `SearchOperationsView.swift` — поиск;
- `ReportsView.swift` — «Отчёты» (четыре вкладки: Структура, Динамика, Остатки, Доходы и расходы; кнопка «Период»); данные для них — `ReportEngine.swift` (без UI, с тестами), фильтр отчёта — `ReportFilter`;
- `YandexFinanceApp.swift` — вкладки, «Отчёты», «Настройки», карточка операции;
- `BankBrowser.swift` — скрытая страница банка, обновление, вход по коду, сохранение (`updateUserData`);
- `Models.swift` — модели и резервная копия; `FinanceEngine.swift` — расчёты (только с тестами).

## Окружение на ПК пользователя (Windows 11)
Всё ниже доступно, если ты работаешь на этом ПК: приложение Codex для Windows с проектом «Finance Test» на папке `C:\Users\dimav\OneDrive\Документы\ios app\yandex-finance-ios-test-main` («Этот компьютер») или Codex CLI из ярлыка «Codex — Finance Test». Пользуйся этими инструментами: запускай проверки и сборку сам. Только облачный Codex (задача в облаке, без папки на этом ПК) работает лишь с репозиторием GitHub: локальных программ у него нет — он правит код и пушит в ветку, проверку и сборку делает GitHub Actions.
- Git for Windows (`C:\Program Files\Git\cmd\git.exe`), доступ к GitHub сохранён в Git Credential Manager.
- Swift 6.4 for Windows — компилирует и запускает финансовые тесты локально (`.local\check.ps1`; SwiftUI/Charts/PDFKit на Windows не собираются — их проверяет GitHub Actions).
- Node.js — встроенный в Bionic: `%LOCALAPPDATA%\Programs\Bionic\resources\app\.webpack-bionic\bin\node.exe` (JS-тесты; `check.ps1` находит его сам).
- Python 3 — для небольших скриптов.
- LM Studio с локальной моделью gpt-oss-20b: сервер включается `%USERPROFILE%\.lmstudio\bin\lms.exe server start --port 1234`, задание — `python .local\lm.py <задание.md> <файлы…>` (ответ в `.local\lm-out`). Годится для мелких задач, ответы проверять: модель путает API.
- `.local\ci.ps1` — сборка в GitHub Actions и скачивание IPA; `.local\check.ps1` — локальные проверки; `.local\apply.py` — применить ответ локальной модели; `.local\gpt.ps1` — вызов Codex из другого агента. Папка `.local` не в git.
- Установка на iPhone — SideStore (iloader на ПК, LocalDevVPN на телефоне): пользователь сам ставит IPA, полученную из сборки.
- Текущие задания этапов — в `docs/STAGE-NN.md`.
