# Обновление 25 — исправление дат финансового движка

В проекте текущий номер сборки — 25.

## Что исправлено

В версии 24 финансовый экран использовал `ISO8601DateFormatter()` только в базовом режиме. Такой форматтер не принимает банковские timestamps с долями секунды, например `2031-02-14T12:34:56.789Z`. Сборщик сохраняет source timestamp через JavaScript `Date.toISOString()`, поэтому реальные операции могли корректно находиться в базе, но молча выпадать из итогов вкладки «Финансы».

Версия 25:

- понимает ISO 8601 timestamps как с долями секунды, так и без них;
- понимает явные смещения часового пояса (`Z`, `+03:00` и т. п.);
- фильтрует период как полуоткрытый интервал `[начало, конец)`, чтобы операция ровно в 00:00 первого числа следующего месяца не попала одновременно в два месяца;
- показывает `Не распознано дат`, если в базе когда-нибудь встретится неизвестный формат даты, вместо молчаливого занижения итогов;
- не меняет рабочий банковский сканер версии 23/24.

## Как проверить v25

1. Установите поверх существующего приложения. Старое приложение и его данные не удаляйте.
2. Полугодовую синхронизацию запускать не нужно.
3. Откройте вкладку `Финансы`.
4. `Операций в периоде` больше не должно быть нулём, если во вкладке `Операции` есть записи текущего месяца.
5. Строка `Не распознано дат` в нормальной базе не должна появляться. Если появилась — сохраните пример `Дата UTC` такой операции для отдельного исправления парсера.
6. После этого можно сверять суммы за одинаковый период с Яндекс Банком.
