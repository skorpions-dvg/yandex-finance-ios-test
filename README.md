# Обновление 22

В проекте текущий номер сборки — 22.

Сводные карточки с явным разделом «N операций» сохраняются одной банковской записью с вложенными составляющими. Проверяются количество, формат всех строк и равенство суммы составляющих итогу. Итог не создаёт третью денежную операцию. Одинаковые суммы не объединяются. Повторное чтение заменяет снимок группы с тем же банковским идентификатором, а не добавляет составляющие повторно. Вложенным строкам не присваиваются вымышленные банковские идентификаторы. Их даты сохраняются в отображённом банком виде, без выдуманного года или часового пояса.

Повторное чтение переключает на вкладку «Банк». Ошибки навигации и таймаут видны в статусе. Месяц сканера отдельно подписан и не называется датой платежа. Дата из URL банка показывается только при её наличии.

Установка: заменить YandexFinance, YandexFinance.xcodeproj, Tests и README.md. Запустить существующий workflow GitHub Actions, установить IPA поверх приложения с прежним Apple ID. Приложение не удалять.

Проверка: отключить автообновление на время проверки, перечитать проблемную карточку через раздел ошибок или открыть её вручную и нажать «Прочитать карточку». Затем открыть сохранённую запись — должны быть видны обе составляющие. Повторить чтение: новая копия группы не должна появиться. Отдельная успешно прочитанная карточка не подтверждает полноту всей истории.

Локально проверены синтетические JavaScript-тесты. Swift/Xcode и реальная страница проверяются в Actions и на iPhone. Общая аналитика доходов/расходов ещё не реализована: связь положительной составляющей с возвратом, а также возможные отдельно показанные банком дочерние операции требуют отдельной сверки до расчёта итогов. Работа закрытого приложения в фоне не гарантируется.
