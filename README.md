# Обновление 26 — понятные итоги и старые списания

В проекте текущий номер сборки — 26.

## Что исправлено

В версии 25 даты уже попадали в месяц, но завершённое списание со старым `kind` становилось «Не определено». Из-за этого расходы текущего месяца были нулевыми, хотя операции в базе были.

Версия 26:

- считает завершённое отрицательное списание расходом, если это не возврат, свой перевод, Сплит, комиссия или незавершённая операция;
- не объявляет непонятное поступление доходом;
- показывает Доходы, Расходы и Разницу, а детали раскрываются;
- возврат уменьшает расходы и не попадает в доходы;
- покупки раскрываются по банковской категории;
- отдельно показывает обработку и строку «Списания с учётом обработки» для сверки с банком;
- не меняет банковский сканер.

## Как проверить v26

1. Установите поверх существующего приложения. Базу не удаляйте и шестимесячную синхронизацию не запускайте.
2. Откройте «Финансы».
3. Для октября контрольные цифры: завершённые списания 17 831 ₽, возврат 1 886 ₽, расход после возврата 15 945 ₽, в обработке 1 635,82 ₽.
4. «Списания с учётом обработки» должны дать 19 466,82 ₽ — ту же сумму списаний, что показывает банк.
5. «Не определено» должно остаться только у непонятного поступления, не у обычных покупок.

## Проверки

GitHub Actions запускает JavaScript-тесты, Swift-тест финансового движка и сборку IPA.
