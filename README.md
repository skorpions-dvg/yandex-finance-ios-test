# Обновление 36.0 — сравнение месяцев

Текущий номер сборки — 36.0.

## Изменения 36.0

- в «Финансах» добавлена секция «К предыдущему месяцу»: доходы, расходы после возвратов и разница — текущее значение, прошлое значение, абсолютное и процентное изменение;
- при нулевой базе процент не вычисляется: рост с 0 ₽ обозначается «новое», неприменимое сравнение — «—»;
- показывается подкатегория расходов с наибольшим ростом в рублях; переводы другим людям, Сплит, возвраты и внутренние перемещения в рейтинг не входят;
- текущий незавершённый месяц помечается как неполный и сравнивается с тем же числом прошедших дней прошлого месяца; если прошлый месяц короче, он берётся целиком;
- финансовые расчёты, категории, PDF-импорт, сканер и хранилище не менялись; сравнение использует существующий FinancialEngine.report.

## Изменения 35.1

- в «Финансах» выбирается месяц: текущий и предыдущие, с переходом через Новый год; переход в будущие месяцы запрещён;
- логика выбора периода вынесена в PeriodSelectionLogic.swift, файл подключён к приложению и к Swift-тестам в GitHub Actions.

## Изменения 34.6.3

- исправлено распознавание переключателя месяца в текущем мобильном интерфейсе истории Яндекс Банка;
- ключ локального шифрованного хранилища теперь имеет защищённую резервную копию внутри контейнера приложения;
- существующая зашифрованная история не перезаписывается, если ключ внезапно недоступен;
- стартовый экран — «Финансы», устаревшие служебные сообщения скрыты, автообновление управляется из интерфейса;
- изменения 34.5–34.6.3 перенесены из временных CI-патчей непосредственно в исходники проекта.
- добавлен отдельный учёт Сейва: переводы Карта ↔ Сейв являются перемещениями, а явные начисления процентов — доходом; старый архив по-прежнему берётся из PDF-выписки.

## Изменения 34.4

По проверенным операциям на iPhone уточнены только правила категорий; финансовая арифметика и банковский сканер не менялись:

- `Яндекс Плюс / Yandex Plus` относится к `Обязательные → Подписки`, даже если банк даёт цифровой MCC;
- `Яндекс.Доставка` относится к `Другое → Доставка и курьеры` и не смешивается с доставкой еды;
- платежи управляющей компании с признаком лицевого счёта относятся к `Обязательные → ЖКХ`;
- получатели вида `горгаз / межрегионгаз` в переводах за лицевой счёт относятся к `Обязательные → ЖКХ`;
- обычные переводы другим людям остаются в `Другое → Переводы другим`;
- правило для газа не затрагивает покупки на АЗС;
- цифровые товары с MCC 5815/5816 без признака подписки по-прежнему относятся к развлечениям.

Новая подкатегория `Доставка и курьеры` доступна для перехода к списку конкретных операций, как и остальные подкатегории. Пересканирование истории для этих исправлений не требуется: используются уже сохранённые название, назначение, категория и MCC.

## Дополнительные исправления 34.3

- Collector распознаёт проценты по явным фразам начисления/выплаты. Переводы и кэшбэк не получают выдуманную категорию «Проценты». В Swift явная категория перевода имеет приоритет над ошибочным старым interest_income.
- Подпись месяца проверяется целиком, с поддержкой известных префиксов и цифрового диапазона. «Мартини бар» больше не считается мартом.
- Уточнены слова «метро» и «АЗС», исключена автоматическая одежда для любых аксессуаров. При отсутствии подтверждения остаётся «Прочее».
- ID операции использует исходный identity без повторного SHA-256. Существующий формат сохранённых данных не меняется.
- Удалены неиспользуемые параметры и передача всей истории в WebView; каждую карточку по-прежнему проверяем, опасный быстрый пропуск не возвращён.
- Нулевая сумма получила отдельное объяснение. Порядок подкатегорий не падает при повторении названия.
- Номер сборки и MARKETING_VERSION — 34.3; инструкция проверки обновлена.

Ранее ошибочно сохранённая категория банка не переписывается вслепую. Если конкретная запись уже получила неверные kind/category от старого Collector, перечитайте только эту карточку; полного сканирования шести месяцев ради обновления не нужно.

JavaScript-тесты выполнены локально. Дополненные Swift-тесты и сборка приложения должны пройти GitHub Actions: локальной Swift/Xcode-среды нет. Ускорение прокрутки на реальном iPhone не измерялось.

## Сохранённые исправления аудита 34.2

- Возврат BNPL/Сплита остаётся в техническом блоке Сплита и не уменьшает расходы, из которых платежи Сплита исключены. Комиссии по-прежнему считаются отдельно.
- Переключение месяца требует подтверждения выбранного периода: смены строк недостаточно. Добавлено распознавание подписи диапазона внутри одного месяца, например 01.10–04.10.
- Отбрасываются невозможные календарные даты и время вместо нормализации JavaScript на другую дату.
- На экране финансов показаны свежесть, незавершённость загрузки и непрочитанные операции. Пояснено отличие оборота сводных карточек от банковского оборота.

Не удалять приложение и не запускать заново шесть месяцев для обновления категорий. Устанавливать поверх с прежним Apple ID.

JavaScript проверен локально. Swift-тесты дополнены, но Swift/Xcode в среде аудита недоступны: выполнение Swift-тестов и сборка IPA остаются обязательным этапом GitHub Actions. Подробный отчёт: AUDIT.md.

## Что добавлено

Версия 34.1 остаётся в том же этапе категорий. Она не меняет проверенную арифметику доходов, расходов, возвратов, pending и банковской сверки, а усиливает точность классификации и навигацию v34.

Расходы теперь группируются так:

- **Еда:** Супермаркеты, Кафе и рестораны, Доставка еды;
- **Транспорт:** Такси, Общественный транспорт, Топливо, Авто;
- **Покупки:** Маркетплейсы, Одежда, Электроника, Дом и быт;
- **Обязательные:** ЖКХ, Связь и интернет, Подписки, Здоровье;
- **Другое:** Развлечения, Путешествия, Подарки, Доставка и курьеры, Переводы другим, Комиссии, Прочее.

После повторного аудита в 34.1 дополнительно исправлено:

- фраза «без комиссии» больше не превращает обычную покупку в комиссию, а настоящая комиссия за перевод между своими счетами остаётся комиссией;
- входящие категории «Переводы» и «Пополнения» распознаются во множественном числе;
- «Перевод между своими счетами» распознаётся и в единственном варианте формулировки;
- текст «Возврат долга/средств» у подтверждённого перевода не превращается в возврат покупки;
- обычное слово «проценты» само по себе не назначает неизвестное поступление процентным доходом;
- банковская категория теперь имеет приоритет над случайными словами в названии магазина; «интернет-магазин» и «мобильное приложение» не считаются автоматически связью/интернетом;
- для слишком общей банковской категории используется безопасный набор точных MCC как дополнительный сигнал (продукты, кафе, такси/транспорт, топливо, электроника, связь, подписки/стриминг, ЖКХ, аптеки, цифровые игры/медиа, кино и путешествия); неизвестные случаи по-прежнему уходят в `Другое → Прочее`, а не угадываются.

Возвраты остаются отдельной корректировкой расходов, а Сплит — отдельным техническим блоком до связывания покупки и платежей.

Доходы сохраняют подкатегории: переводы от других, пополнения, зарплата и выплаты, кэшбэк, проценты и прочие доходы.

## Переход к списаниям

Подкатегории теперь нажимаются. Например:

`Расходы → Еда → Супермаркеты`

открывает список только тех операций текущего периода, которые попали в «Супермаркеты». На экране показаны итог, число операций, дата, название, банковская категория и сумма. Конкретную операцию можно открыть и посмотреть её статус, назначение, MCC и причину финансовой классификации.

Такая же навигация работает для доходных подкатегорий, возвратов, Сплита и перемещений.

Классификация отчёта и фильтр списка используют одну и ту же функцию, поэтому сумма подкатегории и открываемый список не должны расходиться.

## Как проверить v34.4

1. Установите поверх существующей версии. Базу не удаляйте и шестимесячную синхронизацию не запускайте.
2. Откройте «Финансы» и убедитесь, что показана «Сборка 34.4».
3. Проверьте, что итоговые суммы месяца не изменились только из-за новой группировки.
4. Раскройте «Расходы», затем одну из групп и нажмите на подкатегорию. Должен открыться список её операций.
5. Сумма и количество на экране подкатегории должны совпадать со строкой, по которой вы нажали.
6. Если банковская категория не распознана новой схемой, операция должна попасть в `Другое → Прочее`, а не исчезнуть.

## Проверки

GitHub Actions запускает `parser.test.js`, `reliability.test.js`, Swift `FinanceEngineTests.swift` с предупреждениями как ошибками, затем собирает unsigned IPA. Swift-тесты отдельно проверяют весь новый набор пользовательских категорий и стабильный порядок групп/подкатегорий. Тестовые данные синтетические.

## Известные ограничения

- Категории 34.x определяются по банковской категории, описанию, назначению и типу операции. Если банк даёт слишком общее описание, операция безопасно попадает в `Другое → Прочее`. В следующих версиях можно добавить ручное исправление категории и запоминание правил пользователя.
- Перевод на собственную карту в другом банке невозможно надёжно отличить от перевода другому человеку, если банк не пометил его как свой перевод.
- Сплит пока не включается в итог расходов до связывания исходной покупки и платежей.
- Обновление при полностью закрытом приложении iOS/WKWebView не гарантируется.
