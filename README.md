# Обновление 33 — полный аудит финансовой классификации

Текущий номер сборки — 33.

## Что исправлено

Версия 33 сохраняет исправление v32: завершённое отрицательное движение больше не остаётся «Не определено» из-за старого `refund`, `interest_income` или другого противоречивого типа. После специальных случаев (отмена, ожидание, подтверждённый свой перевод, Сплит, комиссия, снятие наличных) оставшаяся отрицательная сумма считается расходом.

Дополнительно после полного аудита:

- технический `unclassified_income` больше не превращается автоматически в доход; неизвестное положительное движение остаётся «Не определено», пока его природа не подтверждена;
- явно распознанные переводы, пополнения, зарплата, кэшбэк и проценты продолжают попадать в доходы;
- «кэшбэк 5 процентов» не перепутывается с начислением процентов;
- положительная сводная операция не угадывается как доход только из-за знака;
- диагностика «Не определено» показывает причину, банковскую категорию, исходный `kind` и статус;
- операции сортируются по разобранной дате, а не только по строке ISO8601;
- ошибки импорта без identity дедуплицируются по ссылке карточки/содержимому, чтобы список ошибок не разрастался дублями;
- во вкладке «Финансы» показывается номер установленной сборки;
- Swift-тест финансового движка в Actions компилируется с `-warnings-as-errors`.

Банковская логика чтения карточек не менялась, кроме обновления номера версии в диагностических текстах Collector.js.

## Как проверить v33

1. Установите поверх текущего приложения. Локальную базу не удаляйте.
2. Откройте «Финансы» и убедитесь, что вверху показана «Сборка 33».
3. Повторная шестимесячная синхронизация для пересчёта старых операций не нужна: финансовый отчёт строится из уже сохранённой истории.
4. Завершённые отрицательные операции должны находиться в расходах, если они не относятся к специальным исключениям.
5. Неизвестное положительное поступление не должно автоматически становиться доходом. Его можно раскрыть в «Не завершено → Не определено» и увидеть диагностические признаки.
6. «Банковские списания/поступления» служат только для сверки банковского оборота и не равны финансовым доходам/расходам.

## Проверки

GitHub Actions запускает `parser.test.js`, `reliability.test.js`, Swift `FinanceEngineTests.swift` с предупреждениями как ошибками, затем собирает unsigned IPA. Тестовые данные синтетические.

## Известные ограничения

- Перевод на собственную карту в другом банке невозможно надёжно отличить от перевода другому человеку только по текущим данным банка, если Яндекс не пометил его как перевод между своими счетами. Такие случаи в будущем потребуют правила/ручной привязки своих счетов.
- Сплит пока показывается отдельно и не включается в итог расходов до связывания исходной покупки и платежей.
- Обновление при полностью закрытом приложении iOS/WKWebView не гарантируется.
