# Обновление 24 — финансовый движок и диагностические итоги

В проекте текущий номер сборки — 24.

Эта версия не меняет рабочий банковский сборщик без необходимости. Поверх уже сохранённых банковских операций добавлен отдельный финансовый слой, чтобы сначала проверить правила учёта, а уже затем строить полноценный пользовательский dashboard.

## Что появилось

В приложении добавлена вкладка **«Финансы»**. Она считает текущий календарный месяц по уже сохранённым операциям и показывает:

- расходы до возвратов;
- возвраты;
- расходы после возвратов;
- доходы;
- чистый денежный поток;
- количество и сумму операций по каждому финансовому типу.

В карточке сохранённой операции теперь видны её финансовый тип и пояснение, почему она отнесена именно туда.

## Правила v24

Финансовая классификация отделена от банковского `kind`, чтобы не менять сырые данные банка.

- обычное списание → `expense`;
- обычное поступление → `income`;
- возврат → `refund`, уменьшает расходы и не считается заработком;
- подтверждённый перевод между своими счетами → `internal_transfer`, не влияет на доходы и расходы;
- выплата процентов → `interest_income`, входит в доход;
- комиссия → `commission`, входит в расход;
- Сплит / BNPL → `split`, пока показывается отдельно и **не входит в обычные расходы**, пока не связаны исходная покупка и платежи;
- явно незавершённая операция → `pending`, не входит в окончательные итоги;
- отменённая/отклонённая операция → `cancelled`, не входит в итоги;
- неподтверждённый тип → `unknown`, приложение его не угадывает и не включает в итог автоматически.

Обычный банковский `transfer`, который **не подтверждён как перевод между своими счетами**, не исключается из расходов автоматически: отрицательная сумма учитывается как расход, положительная — как доход. Это нужно, потому что реальные платежи могут выглядеть как банковский перевод.

### Сводные карточки

Сводная банковская операция учитывается **только по итоговой сумме родительской карточки**. Вложенные составляющие используются как расшифровка и повторно в финансовые итоги не складываются. Например, если банк уже показал согласованный итог группы, две вложенные строки не превращаются ещё в две самостоятельные денежные операции.

## Что намеренно ещё не делается

Это диагностический этап, а не финальный финансовый экран.

- Сплит пока не связывается с исходной покупкой автоматически.
- Неизвестные операции не классифицируются по предположению.
- Нет ручного редактирования категорий и правил магазинов.
- Нет графиков, бюджета, регулярных платежей и прогнозов.
- Суммы на вкладке «Финансы» нужно сверить с Яндекс Банком на одном и том же периоде прежде, чем использовать их как окончательную финансовую аналитику.

## Как проверить v24

1. Установить поверх существующего приложения, старое приложение не удалять — сохранённая база должна остаться.
2. Для первой проверки можно временно выключить **«Обновлять при открытии»**, чтобы результаты не менялись во время сверки.
3. Открыть вкладку **«Финансы»**.
4. Сравнить текущий месяц с Яндекс Банком при одинаковом периоде.
5. Проверить несколько известных примеров в списке операций:
   - возврат должен быть типом «Возврат»;
   - перевод между собственными счетами — «Между своими счетами»;
   - выплата процентов — «Проценты»;
   - операция «В обработке» — «В обработке» и не должна попадать в окончательные расходы;
   - отменённая операция — «Отменено»;
   - сводная карточка должна влиять на итог только своей родительской суммой.
6. Если есть «Не определено», не исправлять данные вручную вслепую: сначала открыть эти операции и проверить, какого признака не хватает для надёжного правила.

Для проверки этого этапа повторная шестимесячная синхронизация не нужна.

## Тесты

GitHub Actions запускает:

- `node Tests/parser.test.js`;
- `node Tests/reliability.test.js`;
- отдельные Swift-тесты `FinanceEngineTests.swift`, которые компилируют настоящий `FinanceEngine.swift` и проверяют расходы, доходы, возвраты, свои переводы, проценты, комиссии, Сплит, pending/cancelled, unknown и сводную операцию без двойного суммирования компонентов;
- затем настоящий `xcodebuild` и упаковку IPA.

Тестовые суммы, даты и идентификаторы синтетические и не должны содержать реальные банковские данные пользователя.
