# Обновление 28 — надёжность финансового слоя и автообновления

В проекте текущий номер сборки — 28.

## Что исправлено

Версия 28 закрывает замечания полной проверки v27, не меняя правила банковского парсинга операций:

- снятие наличных теперь определяется до обычного расхода и относится к «Перемещениям»; комиссия за снятие при этом остаётся комиссией;
- старые операции со статусом «Не указан» больше не растягивают каждое автообновление на месяцы: такие карточки перепроверяются только пока они моложе 14 дней, а явные pending/hold продолжают отслеживаться независимо от возраста;
- финансовый отчёт вычисляется один раз на отрисовку экрана вместо повторного прохода по всей истории для каждого блока;
- ISO8601-парсеры дат больше не создаются заново для каждой операции;
- операции, которые Swift отбрасывает перед сохранением (не RUB или отсутствуют обязательные поля), больше не исчезают молча — итог синхронизации показывает их количество;
- сортировка операций при одинаковом времени получила стабильный второй ключ `identity`;
- «Не завершено» имеет стабильный порядок: «В обработке» → «Не определено» → «Отменено»;
- добавлен безопасный ручной сброс локального зашифрованного хранилища, если ключ/файл больше нельзя открыть; действие требует подтверждения и удаляет только локальную историю;
- диагностические номера в Collector.js приведены к версии 28;
- GitHub Actions запускает parser, reliability, Swift-тест финансового движка и только затем сборку IPA.

## Финансовые правила не изменились

- возвраты уменьшают расходы и не считаются доходом;
- подтверждённые свои переводы и снятие наличных — перемещения;
- непонятное положительное поступление не назначается доходом автоматически;
- Сплит остаётся отдельным блоком до связывания покупки и платежей;
- «Банковские списания/поступления» — оборот для сверки с банком, а не финансовый доход/расход;
- сводная банковская карточка учитывается только по итоговой сумме, её составляющие повторно не суммируются.

## Как проверить v28

1. Установите поверх существующего приложения. Базу не удаляйте.
2. Откройте «Финансы» и убедитесь, что текущий месяц считается без задержки.
3. Если в истории есть снятие наличных, оно должно находиться в «Перемещения → Снятие наличных», а комиссия за снятие — в «Расходы → Комиссии».
4. Обычное автообновление после старых карточек со статусом «Не указан» не должно самопроизвольно уходить на много месяцев назад.
5. После синхронизации при отклонённой Swift-валидацией операции появится явная строка «Не сохранено после проверки: N».
6. Банковские списания/поступления сверяйте с банком на том же периоде; финансовые расходы/доходы оценивайте отдельно.

## Проверки

GitHub Actions запускает JavaScript parser/reliability, Swift `FinanceEngineTests.swift` и сборку IPA. Тестовые операции и суммы синтетические.
