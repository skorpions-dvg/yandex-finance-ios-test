# Обновление 31 — исправление старых списаний в «Не определено»

В проекте текущий номер сборки — 31.

## Что исправлено

Версия 31 исправляет ошибку, обнаруженную на сохранённой истории: завершённые отрицательные операции со старым или неподходящим `kind` могли остановиться в «Не определено», если старый тип выглядел как доход. Теперь после всех специальных правил направление суммы является окончательным fallback: завершённая отрицательная операция считается расходом, а положительная неизвестная операция по-прежнему автоматически доходом не назначается.

Это исправление затрагивает только финансовую классификацию. Банковский сборщик и сохранённая история не требуют повторной шестимесячной загрузки.

Сохраняются все исправления v30: единые pending-статусы, границы 14/45 дней, общий ISO8601-парсер, снятие наличных как перемещение, комиссия за снятие как расход, восстановление хранилища и банковская сверка.

## Как проверить v31

1. Установите поверх текущего приложения, старую базу не удаляйте.
2. Сразу откройте «Финансы» — повторная синхронизация для этой проверки не нужна.
3. Завершённые отрицательные операции больше не должны оставаться в «Не определено» только из-за старого `kind`.
4. Положительные неизвестные поступления всё ещё остаются «Не определено», пока их тип не подтверждён.
5. «Банковские списания/поступления» должны остаться неизменными, потому что меняется только финансовая классификация, а не банковский оборот.

## Проверки

GitHub Actions запускает JavaScript parser/reliability, затем Swift `FinanceEngineTests.swift` (включая отдельные тесты отрицательных операций со старыми income-kind), и только после этого сборку IPA. Тестовые данные синтетические.
