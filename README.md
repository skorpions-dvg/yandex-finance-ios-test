# Тестовая версия для iPhone

Это исходники нативного приложения, а не установочный IPA. Проект предназначен для проверки входа в Яндекс Банк и чтения истории в WKWebView. В среде подготовки нет Xcode и iOS SDK: сборка и запуск на iPhone ещё не выполнены.

## Что реализовано

- Встроенный браузер с локальной постоянной сессией. Вход выполняется пользователем на сайте Яндекса; пароль и коды не считываются приложением.
- «Прочитать карточку»: прочитать подробности одной открытой операции. Начинать тест лучше с этой кнопки.
- При первой синхронизации приложение проходит доступную историю назад по месяцам; после подтверждённого полного прохода автоматическое обновление при открытии проверяет последние 7 дней.
- «Обновить 30 дней» запускает ручную перепроверку последних 30 суток; «Синхронизировать всю историю» принудительно повторяет полный проход.
- Сохранение на телефоне с AES-GCM, ключ в Keychain, файловая защита при блокировке, файл операций исключён из резервного копирования.
- Повторное чтение обновляет запись по банковскому идентификатору, а не добавляет копию. Вкладка «Операции» показывает сохранённые данные без подключения к ПК.
- Возвраты и платежи Сплита выделяются отдельно; положительный платёж Сплита не объявляется доходом.

Автоматическое чтение при открытии реализовано. Гарантированное фоновое расписание при закрытом приложении, аналитика и прогнозы пока не реализованы. Уже разобранные операции сохраняются при отмене/частичном сбое, если JavaScript успел вернуть частичный пакет. Банк не предоставляет здесь проверенный официальный API; изменение сайта может сломать парсер. Мобильные кнопки/диалоги и авторизация могут отличаться от проверенного сайта на ПК.

## Бесплатный путь с Windows

Для бесплатного теста используйте `FREE-SETUP.md`: GitHub Actions собирает Public-репозиторий на стандартной macOS-машине, затем AltStore Classic подписывает IPA локально. Платная подписка Apple и аренда Mac для этого пути не требуются. Этот workflow подготовлен, но ещё не запущен.

## Сборка вручную на Mac (альтернативный путь)

Нужен Mac с Xcode 15 или новее и установленной поддержкой вашей версии iOS. Если iPhone работает на более новой iOS, используйте соответствующий Xcode. Python и Windows-прототип для сборки не нужны.

1. Распакуйте архив на Mac и откройте `YandexFinance.xcodeproj`.
2. В target `YandexFinance` → Signing & Capabilities выберите свою Team. Замените `com.example.YandexFinancePrototype` на уникальный Bundle Identifier, например `ru.yourname.financeprototype`.
3. Сначала выберите симулятор iPhone и выполните Product → Build. Исправляйте ошибки сборки до любых попыток публикации.
4. Для локального Mac: подключите собственный iPhone, настройте доверие/Developer Mode по подсказкам Xcode и выполните Run. Бесплатная Personal Team подходит для локального теста, но подпись ограничена по времени и требует повторной установки.
5. Для удалённого Mac без физического подключения телефона: заранее выберите способ установки. Практичный официальный путь — собственная Apple Developer Program и TestFlight. Создайте запись приложения в App Store Connect, соберите Archive и загрузите через Organizer. Это требует подписания, сведений о приложении и соблюдения требований Apple; готовый ZIP нельзя просто открыть на iPhone как приложение. Внешнее тестирование может требовать проверки Apple.

Не оплачивайте удалённый Mac до выбора способа подписания и установки. Не отправляйте разработчику пароль Apple Account: вход на Mac и выбор Team выполняйте самостоятельно. Этот архив не содержит учётных данных, банковских данных, provisioning profiles или сертификатов.

Для проверки без подписи на Mac:

```sh
xcodebuild -project YandexFinance.xcodeproj -scheme YandexFinance -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

## Тест на устройстве

1. Откройте вкладку «Банк», войдите вручную. Сверяйте отображаемый домен с сайтом Яндекса.
2. Откройте одну операцию → «Прочитать карточку». На вкладке «Операции» сравните сумму, категорию, статус и дату с сайтом.
3. Вернитесь к той же карточке, прочитайте снова: должно быть «добавлено 0».
4. Вернитесь в список, выберите «Все карты и счета» и запустите «Синхронизировать всю историю». Следите за переходами по месяцам.
5. Во время чтения можно открыть Пункт управления/уведомления: состояние `.inactive` больше не отменяет импорт. Кнопка «Остановить» должна сохранить уже разобранные операции.
6. Повторите обновление: без новых операций ожидается «добавлено 0». Сравните несколько покупок, возврат и платёж Сплита.
7. Закройте и снова откройте приложение. После успешного полного прохода автообновление должно проверять только последние 7 дней. Проверьте сохранённые операции и сохранность входа.

Если появилось сообщение «сайт перестал догружать строки», полнота периода не подтверждена. Это может быть конец списка или сбой прокрутки/догрузки. Время без исходной банковской метки берётся из отображаемой даты в часовом поясе устройства с точностью до минуты; это требует сверки на телефоне.

Сеанс браузера и зашифрованные операции находятся в контейнере iOS-приложения. Windows-база защищена другим способом (DPAPI) и сюда не переносится: приложение самостоятельно перечитывает историю. Не используйте симуляторную банковскую сессию на чужом Mac; настоящую авторизацию лучше проверять на своём iPhone.

## Проверки при подготовке

Проверены структура проекта, ссылки на исходники/ресурсы, Swift-синтаксис, plist проекта, синтаксис внедряемого JavaScript и тесты парсера/надёжности: суммы, возврат, Сплит, устойчивый идентификатор, мобильные карточки, переход месяца, пропуски месяцев, частичное сохранение при отмене, фильтры и защитные лимиты. Полная Xcode-сборка, WebKit-вход, шифрование на iOS и реальный импорт всё ещё требуют Xcode и устройства. ZIP не является подтверждением работоспособности приложения.

Официальные справки:
- https://developer.apple.com/xcode/system-requirements/
- https://developer.apple.com/help/account/basics/about-your-developer-account
- https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview

Версия исходников: 0.1.0.
