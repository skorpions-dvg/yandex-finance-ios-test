## Не сделано: нужно разрешённое ТЗ и реализация

1. **Категории банковских доходов в карточке с правилами.** Сейчас правило есть только для расходов. Нужны отдельные необязательные поля для правил/индивидуальных назначений доходов, выбор категории дохода, применение к прошлым и будущим доходам того же отправителя, удаление правила. Назначение категории не должно менять финансовую природу: возврат, перевод между своими счетами, Сплит и незавершённая операция не превращаются в доход. Изменения должны учитываться в поиске, отчётах, карточке и кеше; старые копии открываются.
2. **Обе PDF-выписки в одной истории.** Первый файл содержит архив платёжного счёта, второй — отдельный вклад «Сейв». Текущий выбор допускает один PDF; следующий импорт заменяет весь архив до 01.10.2026. Формат «Сейва» с одной датой без времени не поддержан. Нужны выбор нескольких файлов и последовательное добавление, атомарное сохранение всей выбранной пачки, разделение источников счетов, повторный импорт без дублей, сохранение остальных операций и ручных данных. Проценты «Сейва» должны учитываться как доход; две стороны собственного перевода не должны задваивать финансовые итоги и менять остаток карточного счёта.
3. **Повреждённые названия и пропущенные строки PDF.** Некоторые описания содержат соседнюю дату/сумму вместо получателя; часть таких операций получает неверную финансовую природу. Нужны чтение физической строки таблицы вместо общего порядка текста PDFKit, синтетические тесты многострочных описаний/разных таблиц и безопасная миграция старых записей. Однозначно сопоставленные записи исправлять с сохранением пользовательских назначений; неоднозначные не удалять и не дублировать, показывать результат сверки. Подробнее: `docs/STATEMENT-ROW-ISSUE.md`.
4. **Понятные действия в настройках.** Развести «Экспортировать резервную копию JSON», «Восстановить из копии JSON», «Импортировать PDF-выписки» и «Импортировать разметку категорий». Экспорт JSON сохраняет файл, поэтому не должен предлагаться пользователю как способ выбора PDF.

## Почему реализация остановлена

Пользователь попросил выполнить все пункты, проверить на iPhone, исправить найденное и затем передать Claude на проверку. После первого отказа автоматической проверки пользователь явно подтвердил: **«Да, разрешаю эти изменения без ТЗ Claude»**, включая `Models.swift`, категории доходов в `FinanceEngine.swift`, `StatementImporter.swift`, исправление старых PDF-записей и объединение счетов.

Автоматическая проверка повторно отклонила запись кода даже после этого подтверждения, назвав требование ТЗ Claude из AGENTS.md обязательным. Отказ не обходили. Незавершённый черновик сохранён только локально в `.local/41.10-blocked-draft.patch` и `.local/StatementHistoryMerge-draft.swift`; эти файлы не входят в Git и не являются проверенной реализацией. Все начатые изменения приложения отменены; выпуска 41.10 нет.
