# Ответ DeepSeek о разборе позиций чека (9 октября 2026, переслан владельцем)

Исходный ответ DeepSeek на вопрос о сопоставлении названий и цен в тексте чека без координат. Для GPT (этап 57/58): здесь его тесты 1–7 с точными входами. Ведущий Claude уже разобрал ответ: берём ремонт цены только внутри своего товара и при подтверждении, дубли по итогу, склейку проходов по названию и числам с запасом однозначности, исправление цифр только при единственном варианте; **полный перебор сочетаний (DFS) не берём** — риск зависания на длинном чеке. Все суммы и названия вымышленные.

---

## Главное
1. Строй не «название → все числа до следующего названия», а «название → только распознанные строки колонок этого товара».
2. Сначала вырезай футер (ИТОГ, СКИДКА, ИТОГ БЕЗ СКИДОК), чтобы число из итога не попадало в товар — это убирает ошибку 1.
3. Числовую строку парси как колонки: ЦЕНА, ЦЕНА СО СКИДКОЙ, КОЛ-ВО, ИТОГ; цена позиции — это ИТОГ строки, а не последнее число всей полосы.
4. Если структура строки неоднозначна, не угадывай: оставляй цену пустой и фиксируй расхождение — это убирает ошибку 2.
5. Ремонт цены разрешён только внутри того же товара и только при совпадении признаков: qty, price × qty = rowTotal, сумма строк = ИТОГ.
6. Нельзя брать число из чужой полосы только потому, что оно закрывает gap — это убирает ошибку 3.
7. Два прохода OCR выравнивай не по индексу, а по последовательностям/числам; при похожих названиях решают цены и однозначность — это убирает ошибку 4.
8. Требуй однозначного лучшего соответствия с запасом; если два варианта почти равны — не склеивай, помечай неоднозначность.
9. Одинаковые соседние позиции не схлопывай автоматически: две реальные позиции дают +rowTotal к сумме, повтор OCR — нет — это убирает ошибку 5.
10. Путаницу цифр исправляй только если вариант уникально удовлетворяет price × qty = rowTotal и сумме чека — это убирает ошибку 6.

## 1. Сопоставление названий и цен, проверка по итогу
Не «восстанавливать любой ценой», а строить кандидатов и применять глобальные ограничения. Если решение не единственное — цена пустая, gap в отчёт.

1. Нормализация: верхний регистр, запятая → точка, денежные токены `\d+[.,]\d{2}`.
2. Футер: найти ИТОГ, ИТОГ БЕЗ СКИДОК, СКИДКА. Товарная часть — до первого футера.
3. Сегментация: строка с буквами и без явной числовой колонки — имя. Числовые строки после имени — кандидаты этого товара до следующего имени/футера.
4. Разбор числовой строки: если есть qty и ≥2 чисел — rowTotal = последнее число, price = предпоследнее перед qty, проверка price × qty = rowTotal; если ровно одно число — кандидат rowTotal с низким evidence; если чисел несколько и нет qty/колонок — все числа кандидаты с низким evidence, не выбирать последнее автоматически.
5. Глобальное решение: для каждого товара один rowTotal из его кандидатов или nil; ограничения: сумма rowTotal = ИТОГ; ИТОГ БЕЗ СКИДОК − СКИДКА = ИТОГ (если есть); price × qty = rowTotal для товаров с qty.
6. Единственное решение с максимальным evidence и нулевой коррекцией — применить. Если несколько — применить только цены, совпадающие во всех решениях; gap = ИТОГ − сумма известных.

Ремонт допустим, только если: число в числовой строке этого же товара; есть qty и price × qty = rowTotal или строка с явной колонкой ИТОГ после КОЛ-ВО; после подстановки сумма сходится с ИТОГ; для OCR-цифр — ровно один минимальный набор замен.
Ремонт запрещён: число из другого товара; число из футера; «последнее число полосы» только потому, что сходится итог; замена структурно валидной цены без уникальной OCR-коррекции; несколько глобальных решений.

## 2. Настоящая повторная позиция или повтор OCR
- Две соседние одинаковые позиции с rowTotal: S1 = остальные + rowTotal, S2 = остальные + 2 × rowTotal.
- ИТОГ == S2 и ≠ S1 → две реальные позиции; ИТОГ == S1 и ≠ S2 → повтор OCR, одна.
- ИТОГа нет или оба не сходятся → не схлопывать молча: обе позиции и предупреждение «возможный дубль».
- qty > 1 в одной строке — одна позиция с количеством.
- Если один проход дал дубль, а второй нет — дубль не подтверждён.

## 3. Склейка двух проходов OCR
Выравнивание последовательностей (Нидлман–Вунш): +2 × dice(названий), +3 за точное совпадение rowTotal, +1 за price или qty, штраф за пропуск. Требовать, чтобы лучший вариант был лучше второго на порог; иначе не склеивать участок. Похожие названия, переставленные, с разными ценами — склейка только по имени запрещена. Если порядок перепутан и числа не уникальны — без координат неразрешимо.

## 4. Путаница цифр по контрольным суммам
Замены 3↔2, 8↔6, 5↔6, 1↔7, стоимость 1. Уравнения: price × qty = rowTotal; сумма rowTotal = ИТОГ; ИТОГ БЕЗ СКИДОК − СКИДКА = ИТОГ. Сначала проверить оригинал — сходится, не исправлять. Иначе варианты в 1–2 цифры, поиск с отсечением; минимальная стоимость; если минимумов несколько — не исправлять, gap и предупреждение. Строки товаров исправлять раньше итоговых; qty не трогать без необходимости.

## 5. Тесты DeepSeek (входы и ожидаемый результат)
1. `СЕРВИСНЫЙ СБОР / 100.00 / ИТОГ 120.00` → СЕРВИСНЫЙ СБОР 100.00, gap = 20, предупреждение. Не 120.00.
2. `ТОВАР / 100.00 / 200.00 / ИТОГ 200.00` → ТОВАР 100.00, лишнее 200.00 не привязано, gap = 100, предупреждение.
3. `ТОВАР А / ТОВАР Б / 50.00 / ИТОГ 100.00` → А пусто, Б 50.00, gap = 50. Не подставлять 50 первому.
4. `Йогурт клубника 50 / Йогурт вишня 60` против переставленного второго прохода → две позиции 50 и 60, если числа уникальны; иначе неоднозначность, без чужих цен.
5. `Товар 100 / Товар 100 / ИТОГ 200` → две позиции по 100.00, не одна.
6. `Товар / 73.99 1ШТ 72.99 / ИТОГ 73.99` → цена 73.99, если замена 72.99 → 73.99 уникальна; иначе 72.99 и gap = 1.00.
7. Норма: `Товар А / 36.99 29.99 1ШТ 29.99 / Товар Б / 174.99 174.99 1ШТ 174.99 / ИТОГ 204.98` → А 29.99, Б 174.99, gap 0.

## Что нельзя решить без координат (по словам DeepSeek)
Два одинаковых товара при отсутствии или неоднозначности ИТОГ; два похожих названия с одинаковыми ценами, переставленные во втором проходе; одинокое число в блоке без qty и без сходящегося итога; разрыв, где число не привязано к имени. В этих случаях — пустая цена или неоднозначность и расхождение, а не догадка.
