## 41.16 — экран «Разобрать операции» (главное требование пользователя)
Пользователь хочет пройти неясные операции вручную, чтобы следующие такие же сами попадали в нужную категорию. Названия вроде «IP …», агрегаторов оплаты и «Сервисы Яндекса» по тексту не угадать — только сам пользователь.

Новый файл `YandexFinance/UncategorizedReviewView.swift` (добавить в pbxproj). Вход:
- «Настройки» → «Категории расходов» → строка сверху «Разобрать операции (N)»;
- в «Отчётах», в строке подкатегории «Прочее» и в «Не определено» доходов — та же ссылка, если N > 0.

Что показывать — **по получателю, а не по операции**:
- Расходы: операции, у которых текущая категория (`expenseCategoryID(for:)` → путь) = «Другое / Прочее» (встроенная `ExpenseCategoryGroup.builtin` id категории «Прочее»; если пользователь её переименовал/перенёс — та же по id), **и** нет правила для получателя.
- Доходы: доход, у которого `incomeCategory(for:)` = «Прочие доходы».
- Сгруппировать по `FinancialEngine.counterpartyKey(operation.description)`; строка группы: название (первое описание), число операций, сумма, последняя дата. Сортировка: сначала по сумме по убыванию.
- Нажатие на группу → список операций группы (дата, сумма; нажатие → обычная карточка `OperationDetailView`) и сверху кнопка «Выбрать категорию для всех».
- «Выбрать категорию для всех» → тот же выбор, что `OperationExpenseCategoryView` / `OperationIncomeCategoryView`, но **переключатель «для всех операций» включён и скрыт** — вызвать `setExpenseCategory(id, for: перваяОперация, forPayee: true)` (или `setIncomeCategory(…, forSender: true)`). Это создаёт правило, и все операции получателя уходят из списка.
- Ключ получателя пустой (в названии нет букв) — такие операции показать отдельной секцией «Без названия», выбор только по одной (`forPayee: false`).
- Внизу экрана: «Осталось: N операций, X ₽». Когда пусто — `ContentUnavailableView("Всё разобрано", systemImage: "checkmark.circle")`.
- Сохранение — через `saveExpenseCategoryChange(browser) { … }` (есть в `ExpenseCategoriesView.swift`), ошибка — alert.
- Список строить из `presentation`/`financialInputs` один раз (не вызывать `financialInput(for:)` в цикле для каждой строки — это пересоздаёт индекс на каждую операцию).

Проверка логики без телефона: функцию группировки сделай чистой (`static func groups(_ history: SavedHistory) -> [ReviewGroup]` в отдельном файле без SwiftUI, например `UncategorizedReview.swift`) и добавь её тест в `Tests/FinanceEngineTests.swift` (подключить файл в `.local\check.ps1` не нужно: добавь файл в команду swiftc финансовых тестов в `.github/workflows/build-ios.yml` и в `check.ps1` — **это единственное разрешённое изменение workflow**). Тест: «Прочее» без правила попадает, с правилом — нет; после `setExpenseCategory(…, forPayee: true)` группа исчезает; доход «Прочие доходы» попадает; сумма и число верные.

## 41.17 — замечания пользователя после проверки 41.15
Пользователь проверит 41.15 на iPhone и пришлёт, что не так. Исправляй **по одному пункту за сборку**, если это жесты/вид. Что уже сделано и что именно он должен проверить в 41.15:

2. Диагональный свайп между вкладками: старая страница не должна уезжать вниз.
3. В «Отчётах» текст не уходит под нижнюю панель.
4. Счета: карандаш включает редактирование, панель не закрывается.
5. Версия и сборка видны внизу настроек обычной прокруткой.
6. «Обои» → нажать «Настройки» внизу → возврат к началу настроек.
7. 16 обоев, из них 4 новых рисунка (не пейзажи).
8. «Импортировать PDF-выписки» → выбрать **оба** файла сразу → диалог с числами → «Применить». Проценты «Сейва» в доходах, переводы на «Сейв» не стали доходом/расходом, остаток карты не изменился. Повтор с теми же файлами — «новых операций нет».

Если пункт 1–4 не исправлен — сначала спроси у пользователя короткое видео/скриншот, потом одна правка — одна сборка. После двух неудачных попыток по одному пункту — передать Claude с описанием, что пробовал.
