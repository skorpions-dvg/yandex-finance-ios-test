# Этап 41 — свои категории расходов и смена категории операции (ТЗ для GPT)

Ветка: `stage-41`. Прочитай сначала `AGENTS.md`. Основа (модель, правила, расчёты) сделана ведущим в 41.1 и покрыта тестами (`testExpenseCategories`, `testFixedCostGroups`) — **её не меняй**, только используй. Если чего-то не хватает в модели — не дописывай сам, напиши ведущему.

Этап только про **расходы**. Категории доходов пока остаются как есть (`incomeSubcategoryOrder`).

## Что уже есть (не трогать)
`Models.swift`:
- Дерево пользователя: `history.categoryTree: [ExpenseCategoryGroup]` (до первой правки — встроенное `ExpenseCategoryGroup.builtin`, id у него постоянные).
  - `ExpenseCategoryGroup { id, name, isFixedCosts, categories: [ExpenseCategory] }`;
  - `ExpenseCategory { id, name, sources }` (`sources` — служебное, не показывать).
- `history.expenseTaxonomy` — то же дерево для движка (порядок в отчётах, сравнение месяцев, прогноз).
- `history.financialInputs` — **все** операции (банк + ручные) с учётом выбранных категорий. Это замена `history.allOperations.map(\.financialInput)`.
- `history.financialInput(for: operation)` — то же для одной операции.
- `history.expenseCategoryID(for: operation) -> UUID?` — текущая категория расхода (nil — не расход: доход, возврат, перевод, сплит, в обработке).
- `history.expenseCategory(id:) -> (group, category)?`.
- Правка дерева (все возвращают `Bool`/`UUID?`; `false`/`nil` — нельзя: пустое имя, «/» в имени, повтор имени, «Сплит»/«Возвраты» как группа):
  `addExpenseGroup(name:)`, `addExpenseCategory(name:groupID:)`, `renameExpenseGroup(_:to:)`, `renameExpenseCategory(_:to:)`, `setFixedCosts(_:groupID:)`, `moveExpenseGroup(_:to:)` (индекс в итоговом порядке), `moveExpenseCategory(_:toGroup:at:)` (индекс в итоговом порядке группы-цели), `deleteExpenseCategory(_:mergingInto:)`, `deleteExpenseGroup(_:mergingInto:)` (цель — категория **другой** группы).
  Ручные операции, правила и выбранные категории при переименовании/переносе/удалении обновляются сами.
- Смена категории операции: `setExpenseCategory(categoryID, for: operation, forPayee: Bool)`.
  `forPayee: true` — правило «все расходы этого получателя → категория» (прошлые и будущие); `false` — только эта операция (сильнее правила). Для ручной операции просто меняет её категорию.
- Правила: `history.categoryRules: [CategoryRule]?` (`title` — название операции, `categoryID`), удаление `removeCategoryRule(id)`.

`FinanceEngine.swift`: `report(_:in:taxonomy:)`, `compareReports(_:currentInterval:previousInterval:taxonomy:)`, `monthForecast(_:now:calendar:taxonomy:)` — новый необязательный параметр `taxonomy`.

Все изменения — только через `browser.updateUserData { history in … }` и методы выше (они меняют `history` внутри замыкания). Если метод вернул `false` — показать короткое сообщение и ничего не сохранять.

## 41.2 — подключить категории пользователя везде (механическая замена)
- Везде, где сейчас `browser.history.allOperations.map(\.financialInput)` (главный экран, прогноз, запас, «Отчёты», сравнение месяцев, график категорий) → `browser.history.financialInputs`.
- В вызовы `FinancialEngine.report`, `compareReports`, `monthForecast` в интерфейсе передать `taxonomy: browser.history.expenseTaxonomy`.
- `SearchOperationsView`: `FinancialEngine.operationMatches(browser.history.financialInput(for: $0), query:)` (лучше один раз построить `history.financialInputs` и сопоставить по индексу с `allOperations` — порядок одинаковый).
- `FinanceCategoryOperationsView` / `FinanceOperationSelection.matches`: категорию брать из `history.financialInput(for: operation)` (иначе список по категории в «Отчётах» не совпадёт с суммой).
- `OperationRow`: подпись категории и иконка группы для расхода — по категории пользователя (передать в строку уже готовый `FinancialOperationInput` или путь категории). Иконки встроенных групп как сейчас; для новых групп — `square.grid.2x2.fill` серый.
- `ManualOperationFormView`: список групп и категорий брать из `history.categoryTree` вместо `expenseGroupOrder` / `expenseCategory`-списков.
- Сборкой без правок дерева всё должно выглядеть **как в 40.6** (суммы те же).

## 41.3 — экран «Категории»
«Настройки» → строка «Категории расходов» → экран в стиле страницы счетов (`AccountsView`, Money Flow: plain список, группы — заголовки со сворачиванием).
- Группа: название, справа сумма расходов за текущий месяц (по `report(...).expenseLines`). Категории внутри — иконка группы, название, сумма за месяц.
- Карандаш сверху справа → режим правки **на месте** (как на странице счетов): перетаскивание групп и категорий за ручку (категорию можно перетащить в другую группу — `moveExpenseCategory`), удаление свайпом/кнопкой.
- «+» → меню: «Группа» / «Категория» (для категории — выбор группы). Форма — sheet с полем названия, как `AccountGroupFormView`.
- Нажатие на группу в режиме правки → форма группы: название, переключатель «Обязательные платежи» (`isFixedCosts`, подпись: «Крупные платежи этой группы не считаются разовыми в прогнозе»). Нажатие на категорию → форма: название.
- Удаление категории или группы: всегда спросить «Куда перенести операции?» — список категорий (для группы — только других групп), затем подтверждение «Удалить „…“? Операции перейдут в „…“». Последнюю категорию удалить нельзя.
- Внизу экрана раздел «Правила»: строки «<название операции> → <группа> / <категория>», удаление свайпом. Если правил нет — раздел не показывать.

## 41.4 — смена категории у операции
- Карточка банковской операции (`OperationDetailView`), если `expenseCategoryID(for:)` не nil: строка «Категория: Группа / Категория» с переходом в выбор категории.
- Выбор категории: список групп и категорий из `categoryTree` (текущая — с галочкой). Под списком переключатель «Для всех операций „<название>“» — по умолчанию **включён**; подпись: «Прошлые и будущие расходы этого получателя тоже перейдут в эту категорию».
- После выбора: `setExpenseCategory(id, for: operation, forPayee: переключатель)`, вернуться в карточку — там уже новая категория; на главном экране и в «Отчётах» суммы перераспределились.
- Для ручных операций выбор категории остаётся в их форме (41.2).
