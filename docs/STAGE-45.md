## 45.1 — подсказки категории (чистая логика + тесты)
Новый файл `YandexFinance/CategorySuggestions.swift` (только Foundation, без SwiftUI; зарегистрировать в `project.pbxproj` по образцу `ReceiptParser.swift`; добавить в `.local/check.ps1` и в строку компиляции «Проверка финансового движка Swift» в `.github/workflows/build-ios.yml` — единственная разрешённая правка workflow).

```swift
struct CategorySuggestion: Equatable, Identifiable {
    enum Reason { case history, words, similarPayees }
    let categoryID: UUID          // из дерева пользователя
    let group: String
    let subcategory: String
    let reason: Reason
    let count: Int                // на скольких операциях основана
    var id: UUID { categoryID }
}

struct RuleCandidate: Equatable, Identifiable {
    let payeeKey: String
    let title: String             // название получателя для показа
    let categoryID: UUID
    let operationCount: Int       // сколько прошлых операций получателя правило затронет
    var id: String { payeeKey }
}

enum CategorySuggestions {
    /// До трёх разных категорий для группы получателя, лучшая первой; «Другое/Прочее» не предлагается никогда.
    static func suggest(for group: ReviewGroup, history: SavedHistory) -> [CategorySuggestion]
    /// Получатели без правила, у которых есть минимум три расхода с одной и той же выбранной вручную категорией
    /// и ни одного расхода с другой выбранной вручную категорией.
    static func ruleCandidates(_ history: SavedHistory) -> [RuleCandidate]
}
```
Правила подсказок, в порядке силы:
1. `.history` — у того же `payeeKey` есть другие расходы (не вошедшие в группу «Прочее»), чья текущая категория не «Прочее»: берётся самая частая (минимум 1 операция); при равенстве — более свежая.
2. `.words` — `ReceiptParser.keywordCategory` по названию получателя, если такая категория есть в дереве пользователя.
3. `.similarPayees` — получатели с тем же первым значимым словом названия (минимум 4 буквы), у которых не «Прочее»: подсказывать только если одна категория составляет не менее 80 % и таких операций не меньше двух. Это самая слабая подсказка.
Для группы без `key` (нет надёжного ключа) подсказки только по `.words`. Доходы подсказок не получают (возвращается пустой массив).

`ruleCandidates`: учитывай только банковские расходы (не ручные), только `payeeKey` не пустые и без `categoryRules` записи; `categoryOverrides` с одинаковой `categoryID` ≥ 3 операций, и нет операций этого получателя с другой выбранной вручную категорией.

**Тесты в `Tests/FinanceEngineTests.swift`** (только выдуманные названия; проверка `privacy.test.js`): каждая причина подсказки; порядок и не более трёх; «Прочее» не предлагается; группа без ключа; доходы без подсказок; ничья по частоте; кандидаты: ровно три одинаковых выбора, конфликт категорий, уже есть правило, пустой ключ, ручные операции.

## 45.2 — быстрый разбор (интерфейс)
В `UncategorizedReviewView.swift` и `ReviewGroupOperationsView` (новые вспомогательные виды — в новом файле `QuickReviewViews.swift`):
1. **Шапка списка:** «Осталось N получателей · M операций · X ₽» вместо одной строки внизу; при N = 0 прежнее «Всё разобрано».
2. **Строка группы:** под названием маленькая подсказка лучшей категории («Еда / Супермаркеты · по прошлым покупкам», «по словам в названии», «по похожим получателям») — если подсказка есть.
3. **Раздел «Предложения правил»** вверху списка (если `ruleCandidates` не пуст): строка «<название> → <категория> · N операций», кнопка «Применять всегда». Применение: `setExpenseCategory(categoryID, for: <любая операция получателя>, forPayee: true)` через `browser.updateUserData`.
4. **Экран группы:** над кнопкой «Выбрать категорию для всех» до трёх кнопок-подсказок (`CategorySuggestions.suggest`): нажатие сразу ставит категорию для всех операций получателя (если `group.appliesToAll`) либо для одной (для групп без ключа и ручных операций — как сейчас) и **переходит к следующей группе** списка; если следующей нет — возвращается к списку.
5. **Отмена:** после любого применения внизу экрана на 6 секунд панель «Применено · Отменить». «Отменить» возвращает **только два поля** — `categoryRules` и `categoryOverrides` — к значениям до действия (скопируй их перед применением), чтобы не затронуть остальные изменения истории.
6. Строка «Другая категория…» оставляет прежний путь через `OperationExpenseCategoryView`.
7. Вход: в «Настройки → Категории расходов» строка «Разобрать операции (N)» остаётся; дополнительно в «Отчётах → Структура» (расходы, нет фильтра) под списком групп, если в «Другое/Прочее» больше 10 % суммы и есть группы к разбору — одна строка-ссылка «Разобрать «Прочее»: N получателей» на этот же экран. Другие места не менять.

## Что проверить на iPhone
1. «Настройки → Категории расходов → Разобрать операции»: наверху «Осталось N получателей · M операций · X ₽».
2. У групп с историей видны подсказки; открыть группу, нажать подсказку: категория ставится всем операциям получателя, открывается следующая группа, внизу «Применено · Отменить».
3. «Отменить» возвращает прежнюю категорию, остальные данные не меняются (проверить суммы в отчёте «Структура» до и после).
4. «Предложения правил»: «Применять всегда» превращает три и более ручных выбора в правило; новая операция того же получателя сразу идёт в эту категорию.
5. Подсказки не предлагают «Прочее»; доходы разбираются как раньше.
6. Скорость: список и экран группы без заметной задержки (подсказки считаются один раз через кеш).
