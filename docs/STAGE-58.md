## Задача 2 — тесты будущей сверки чека с операцией банка (только тесты, не из `main()`)
Функция появится в блоке «Доработки» как чистая (без UIKit). Контракт, по которому писать ожидаемые результаты (`testKnownReceiptMatch58()`, печатать expected/actual):

```
ReceiptBankMatch.match(totalKopecks: Int64?, date: Date?, hasTime: Bool, operations: [FinancialOperationInput]) -> Outcome
enum Outcome { case confirmed(identity: String, timeFix: Date?), ambiguous([String]), none }
```
Правила:
- кандидаты — операции-расходы банка (не ручные), |сумма| равна итогу чека в копейках или отличается заменой одной цифры по парам 3↔2, 8↔6, 5↔6, 1↔7;
- дата операции в пределах ±1 календарного дня от даты чека;
- балл: точная сумма 100, исправленная 40; тот же день 50, соседний 20; время (только если `hasTime`) — до 60 баллов, минус 1 за каждую минуту разницы;
- `confirmed`, только если лучший балл больше второго минимум на 20; иначе `ambiguous` (до 5 кандидатов); нет кандидатов — `none`;
- `timeFix` — время операции банка, только если `hasTime` и разница ≤ 15 минут; иначе nil. Сумма чека никогда не меняется.

Случаи (вымышленные суммы): однозначный матч; разница 10 мин (18:27 → 18:37); через полночь (23:58 и 00:05 следующего дня); две одинаковые суммы в один день → ambiguous; дата через 5 дней → none; исправленная цифра (729,99 против 739,99); несовпадающая сумма → none; чек без времени (время не входит в балл, `timeFix` nil); ручная операция с той же суммой не кандидат; отменённая операция не кандидат; операция «в обработке» — кандидат.

Данные вымышленные (`privacy.test.js`).
