# Для проверки ведущим: порядок строк PDF при импорте

При локальной сверке резервной копии с исходной PDF-выпиской обнаружено:

- часть `statement:` операций содержит в `description` и `purpose` дату, карту и суммы соседней строки вместо названия;
- собственные `occurredAt` и `amountKopecks` этих записей сопоставляются с другой, полноценной строкой таблицы PDF;
- из-за утраты описания платежи Сплита и перевод между своими счетами могут получить обычный тип расхода;
- PDF содержит две выписки последовательно, а переносы текста и порядок извлечения столбцов требуют отдельной проверки.

Это проблема получения исходных данных, а не дерева пользовательских категорий. В 41.9 `StatementImporter.swift`, `Models.swift`, `FinanceEngine.swift` и тесты основы 41.1 не изменены.

Нужны ТЗ и проверка ведущего: синтетический PDF с многострочными названиями и несколькими таблицами, восстановление соответствия описания/даты/суммы, безопасная миграция уже импортированных записей без дублей, сохранение пользовательских категорий и ручных операций. Простое повторное импортирование не подходит: идентификатор выписки зависит от описания строки.

Личные PDF, JSON, названия получателей и результаты сверки находятся только вне отслеживаемых файлов. Импорт разметки в 41.9 меняет только категории; он не исправляет финансовую природу повреждённых записей.
